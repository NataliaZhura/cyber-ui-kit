# Прогноз ставок до 2030 (`/prognoz`) — рабочая модель

**Полувагоны (обычный и инновационный) — только `zrate.py`**, крытые, зерновозы, фитинговые платформы — `ztypes.py`
(та же схема, три сценария, стоимость вагона;
`zmodel.py` — только если человек выбрал свой набор показателей в пункте ④). Всё запускается через `zrate.py run --pick`. **Цифры только из файла программы** — сама не считай, не округляй по-своему, не придумывай.
Тот же расчёт — в Excel-моделях владельца и в мини-приложении.

**Запрещено для полувагонов:** `zmodel.py` (его меню, «рекомендуемый набор», «надёжность направления», «константа»),
свой «якорь» или своя средняя, подбор закупок/списаний под нужную ставку (вместо этого — раздел «Что нужно…» из файла
`zrate.py`), смешивать цифры двух программ. PDF — только из файла программы через `zreport.py`, без дописанных расчётов.
Нет `forecast/rate_data.json` — ответь «Модель полувагонов ещё не загружена на сервер (zrate.sh)» и ничего не считай.

**Средние — всегда с пометкой периода**, как в файле программы: «средняя за 2027 г. (январь–декабрь)», «средняя за
2026 г. (январь–декабрь: январь–сентябрь — факт, октябрь–декабрь — прогноз)», «ставка месяца» (октябрь, ноябрь, декабрь),
«на конец года (декабрь)». Голую цифру без пометки не пиши.

## Меню — одним сообщением

`python3 ~/railway-monitor/zrate.py menu` — пришли вывод **дословно** (своё меню не составляй, старое меню
`zmodel.py menu` не присылай). Ответ человека — 3 числа «вагон период сценарий» (например `2 1 4`), для крытых —
ещё показатели (`4 1 1 0`), или «П». Если в запросе уже всё сказано («прогноз инновационного на 2028 оптимистичный») —
меню не присылай, сразу считай: `--pick "2 4 2"`.

Сценарий 5 (свой): что изменить — из текста ответа, в `--set`. Полувагоны (действует с 2027 г.; одно число на все годы
или четыре через «;»): `coal` уголь, `load` погрузка на сети, `turn` замедление оборота, `stroy` стройка — % за год;
`buy` выпуск, `off` списания — тыс. вагонов в год; `pace` — рабочий парк в IV кв. 2026, % в месяц (сокращение — минус).
Крытые (рабочая модель): `stroy` стройка, `mortgage` ипотека год назад — % за год; `pace` — темп ставки в IV кв., % в
месяц. Зерновоз (6, 7): `export` экспорт зерна, `park` рост парка зерновозов — % за год. Платформы (8–10): `balance` —
рост контейнерных перевозок минус рост парка платформ, % за год (модель платформ слабая — подчеркни: «прогноз сценарный»). Со своим набором показателей (④) — коды `zmodel.py`: coal, load, turnover, stroy, mortgage, housing, gdp, key, tariff,
price, buy, off.

## Как посчитать и отдать

1. `python3 ~/railway-monitor/zrate.py run --pick "<ответ>" [--set coal=2,off=35,pace=-1.5]
   --out ~/railway-monitor/saved/prognoz/ГГГГ-ММ-ДД_прогноз_ставок_<вагон>.md`. Гостю — добавь `--guest`, папка
   `saved_<агент>/prognoz/`. Ошибка программы («напиши, что изменить», «со своим набором оптимистичного нет») — перескажи
   её одной строкой и предложи вариант.
2. PDF: `~/pw/bin/python ~/railway-monitor/zreport.py <файл.md>`; отправка — владельцу `send.py <pdf>`, гостю
   `send.py --to <ID> <pdf>` + копия владельцу по гостевым правилам.
3. В чат — строки таблицы «Коротко» из файла **вместе с пометками** у каждой цифры, по образцу:
   «Инновационный полувагон, ₽/сут без НДС, средняя за год (январь–декабрь):
   • Базовый: 2026 — 1 225 · 2027 — 1 612 · 2030 — 2 673; ставка декабря 2026 — 1 527
   2026 — январь–сентябрь факт + октябрь–декабрь прогноз.» Затем главный фактор из раздела 4 и «Полный расчёт — в PDF». Источник рыночных ставок не называй — «данные рынка».
   Крытые со своим набором (④) — ещё надёжность набора (слово из файла); «⚠ Набор … ненадёжен» — первой строкой.

Другие команды полувагонов:
- «Будет ли 1 500 / 1 560» — раздел «Что нужно, чтобы ставка была выше …» из файла (`run --wagon inno`).
- «Куда идёт рынок»: `python3 ~/railway-monitor/zrate.py track coal=<%> load=<%> stroy=<%> netoff=<тыс.> workcut=<%>`
  — значения из сводки рынка или новостей (netoff — списания минус выпуск; workcut — сокращение рабочего парка, %).
- Финмодель и стресс-тест: выручка — `zrate.py run --wagon gon|inno`, крытые — `ztypes.py run --wagon kr158|kr138` (три сценария).

## Готовый документ (ответ «П»)

Владельцу — два файла:
1. Полувагоны: `python3 ~/railway-monitor/send.py ~/railway-monitor/forecast/Модель_ставки_полувагона_2030.pdf`
   (Excel — `forecast/Модель_ставки_полувагона_2030.xlsx`, если просят).
2. Крытые: `python3 ~/railway-monitor/send.py ~/railway-monitor/forecast/Прогноз_ставок_вагонов_2030.pdf`
   («подробно» — ещё `forecast/Приложение_факторы_и_источники.pdf`).

Гостю: полувагоны — `zrate.py run --guest --out saved_<агент>/prognoz/ГГГГ-ММ-ДД_модель_полувагона.md` → PDF →
`send.py --to <ID>`; крытые — только `forecast/guest/Прогноз_ставок_вагонов_2030.pdf`.

В чат — 3 строки: полувагон инновационный, средняя за 2030 г. (январь–декабрь): базовый / оптимистичный /
пессимистичный — из «Коротко» файла `zrate.py`; крытый 158 м³, средняя за 2030 г. — из «Коротко» файла
`ztypes.py run --wagon kr158`; «актуальные прогнозы — в модели (первый файл и /prognoz); в презентации крытых — прежний
расчёт, только справочно». Цифры документов не пересчитывай и не меняй.

Вопросы «почему такая цифра» — по разделам «Из чего складывается рост» и «Цена фактора» (полувагоны), «Что двигает
прогноз» (крытые). Обновить данные модели — «обновлённую версию готовит владелец».
